# Лабораторная работа 4. Отображаемые файлы (вариант 3)

## Задание

Вариант взят из лабораторной работы 2. Родительская программа `parent` читает имя выходного файла из первой строки и запускает отдельную программу `child`. Следующие строки содержат целые числа типа `int`, разделённые пробельными символами. Дочерний процесс последовательно делит первое число на остальные и записывает один результат на строку. Если очередной делитель равен нулю, `child` сообщает об этом родителю и оба процесса завершаются.

Для обмена в этой работе используется файл, отображённый в память обоих процессов через `mmap` с флагом `MAP_SHARED`.

```text
клавиатура → parent → [строка в общем отображении] → child → файл результатов
             parent ← [код ответа в общем отображении] ← child
```

## Сборка и запуск

Linux, GCC и Make. Запускать из папки `lab4`, где лежит исполняемый файл `./child`.

```bash
make
./parent
make clean    # удалить parent и child
```

Пример с перенаправленным вводом.

```bash
printf 'out.txt\n100 5 2\n10 abc\n7 0\n12 2\n' | ./parent
cat out.txt
```

`100 5 2` даёт `10`. Строка `10 abc` вызывает сообщение «некорректная строка». На `7 0` оба процесса завершаются, поэтому в `out.txt` остаётся только `10`. При обычном завершении ввода нажмите **Ctrl+D** на пустой строке. Дочерний процесс создаёт выходной файл или очищает уже существующий файл с введённым именем.

## Структура проекта

| Файл | Содержимое |
|---|---|
| `parent.c` | Ввод, создание файла обмена, `fork` и `exec`, отправка запросов, ожидание ответа и `waitpid` |
| `child.c` | Подключение к отображению, обработка строк, запись результата и отправка ответа |
| `utils.c`, `utils.h` | Разбор целых чисел, целочисленное деление, структура заголовка и коды ответа |
| `Makefile` | Сборка обеих программ |

## Как работает обмен

1. `parent` создаёт временный файл через `mkstemp` и удаляет его имя через `unlink`. Сам файл остаётся доступен через открытый дескриптор. `posix_fallocate` выделяет место под заголовок и при необходимости под строку. Файл автоматически освобождается, когда закрыты дескрипторы и сняты отображения.
2. Родитель отображает заголовок и инициализирует в нём два семафора с `pshared = 1` и начальным значением 0. После `fork` дочерний процесс наследует дескриптор. `execl` передаёт его номер и имя файла результатов новой программе. `child` заново отображает заголовок и сигнализирует о готовности после открытия выходного файла.
3. `parent` читает строку через `getline`, отображает участок файла нужной длины и копирует строку сразу после заголовка. Затем записывает её размер в заголовок и вызывает `sem_post` для `request_ready`.
4. `child` просыпается после `sem_wait`, отображает тот же участок и разбирает строку. При успехе он записывает число в файл результатов. Затем публикует код ответа в заголовке и вызывает `sem_post` для `reply_ready`. Следующую строку родитель отправляет только после получения ответа, поэтому дочерний процесс успевает прочитать предыдущую целиком.
5. При конце ввода родитель передаёт размер 0 и будит `child`. При делении на ноль дочерний процесс отправляет код `DIV_ZERO` и сам выходит из цикла. В обоих случаях `parent` забирает статус дочернего процесса через `waitpid` и освобождает ресурсы.

`MAP_SHARED` связывает отображения с одним файлом, хотя виртуальные адреса у процессов могут отличаться. Семафоры задают порядок доступа к общим полям. В заголовке хранятся размер и код ответа, а сама строка лежит в файле по смещению `sizeof(Shared)`. Размер отображения для строки зависит от длины ввода.

## Ошибки и крайние случаи

| Ввод или ситуация | Поведение |
|---|---|
| `-7 2` | Результат `-3`, целочисленное деление округляет к нулю |
| `42` | Результат `42`, делителей нет |
| Пустая строка, посторонний символ или число вне диапазона `int` | `DIV_ERROR`, работа продолжается |
| `-2147483648 -1` | `DIV_ERROR`, итог не помещается в `int`. Промежуточное значение вычисляется в `int64_t` |
| `7 0` | `DIV_ZERO`, оба процесса завершаются |
| Ошибка открытия или записи файла результатов | `child` печатает причину, `parent` возвращает ненулевой код |
| `child` завершился во время ожидания ответа | После тайм-аута семафора родитель обнаруживает завершение через `waitid`, затем забирает статус через `waitpid` |

Тайм-аут в одну секунду нужен для проверки состояния дочернего процесса. Пока тот работает, родитель продолжает ждать. При штатном обмене `sem_post` пробуждает его сразу.

## Демонстрация на защите

Запустите `./parent`, введите имя файла и оставьте программу ждать чисел. Во втором терминале подставьте PID из сообщения «запущен child».

```bash
parent_pid=1234
child_pid=1235
ps -o pid,ppid,stat,comm -p "$parent_pid,$child_pid"
grep -H '/tmp/lab4-' "/proc/$parent_pid/maps" "/proc/$child_pid/maps"
```

В обоих файлах `maps` у отображения будет признак `rw-s` и совпадут устройство и inode. Пометка `(deleted)` появляется после удаления имени временного файла через `unlink`.

Команда для трассировки запуска, отображения и завершения процессов.

```bash
strace -f -e trace=execve,openat,unlink,fallocate,mmap,munmap,clone,wait4,waitid,futex ./parent
```

В выводе ищите запуск `./child` через `execve`, отображения `MAP_SHARED` в обоих процессах и вызов `wait4` у родителя. Когда ожидание семафора блокирует процесс, в Linux оно видно как `futex`.

При проверке оба процесса показали один inode в `/proc/*/maps`. Также проверены Ctrl+D, строка из 150 001 числа, ошибки открытия и записи результата и принудительное завершение дочернего процесса во время обмена.
